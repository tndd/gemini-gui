## セッションの累積
新しいセッションを開くたび、疑似ターミナルが開かれる。
だが、新しいチャットをユーザーが始めても、古いセッションのターミナルは閉じられない。結果としてアプリのサイズがデカくなってしまう。

## welcomeページからchat画面への遷移
welcomeページの送信ボタンを押してからのchat画面への遷移が遅い。
期待される動作は、すぐにチャット画面に遷移しそこで回答を待つこと。

## active session
古いチャットへのアクセスを遮断するために必要。
終わったセッションに対話を無理やり続けても、gemini側ではもうコンテキストが失われてるんだから無意味。

経過:
- いくつか選択肢はあるが、dbへの保存という択は取りたくない
  - active session状態という状態の性質を鑑みると、揮発的な性質を持っていてほしい
  - なるべく簡素な実装にすること。それが最優先。
